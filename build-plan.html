01 · The core loop

Nobody pastes headlines. Networth comes to them.

1

Watch

Pull news all day on the Maritime VM.

2

Confirm

Group articles into stories. A story counts only when several original publishers carry it. Wire reposts don't count twice.

3

Trigger

Price first: an asset made an unusual move, so find the story behind it. News first: a big story of a known type.

4

Measure

Look up base rates from the engine. Two numbers each: after events like this, and in any random window.

5

Rank

Keep only what touches the user's holdings. Most days that's 0 to 3 items.

6

Push

7am brief, a rare alert, then answer follow-ups about their own money.

02 · Data shape

The engine makes every number. The LLM only explains.

// hand-curated + seeded from public lists
Event    { id, date, type, cause, region,
           headline, sources[], episode_id }

// precomputed by the backtest script
Reaction { event_id, asset, horizon, excess_return }

// what the agent reads, and nothing else
BaseRate { type, cause, asset, horizon, era,
           n_events, n_episodes,
           hit_rate, baseline_hit_rate,
           median, p10, p90 }

// per user, from onboarding
Profile  { user_id, holdings[], watch[], brief_time }

horizon fixed per event type in advance
era     ∈ { since_1926, since_1998 }

Rules from the investor research

  • Two base rates, always. "After events like this" next to "in any random window". Most assets rise in most windows anyway.
  • Count episodes, not events. Events within 21 trading days merge into one episode. 2008 doesn't count 30 times.
  • Tag the cause, not just the size. Oil rising on demand behaves unlike oil rising on a supply shock.
  • Fix the horizon per event type up front. Picking the best-looking window afterwards is data mining.
  • Two eras. Since 1926 via the Kenneth French industry portfolios, and since 1998 via tradeable ETFs. Disagreement between them is shown.
  • Under 8 episodes says "weak signal", in words and in numbers like "8 of 11".

Where each idea comes from

  • zoya-harness, reused as is. SKILL.md loader with per-skill tool limits, router, task budget limits, model adapter, eval replay. Voice and Mac parts removed.
  • SimbianOS, as a pattern only. One spec file per agent with permissions and budget together. Stop on budget or goal. Tools loaded only when called. Sub-agents built by the same factory with narrower permissions. No security code, no multi-tenant machinery.
  • investment-os, your Oct 16 design. Every number in a message must match the engine, or the message is blocked. Point-in-time rules so the backtest can't peek at the future.
  • autoresearch and harness2, as ideas. A frozen eval, one editable file, keep or discard. See section 06.

06 · Getting better on its own

One loop, tested on history it hasn't seen.

The loop

  • Frozen test. Walk forward through history. Using only events before year Y, predict sector direction after events in year Y. Score calibration: did "8 of 11" happen about 73% of the time?
  • Editable. odds.py (matching, era weights, similarity) and the explanation prompts.
  • Keep or discard. A change stays only if the train score improves and the held-out score doesn't drop. Each kept change is a git commit plus a line in lessons.md.
  • Locked vault. Events from 2022 to 2026 never enter the loop. They're the final check.

The outside check

Before trusting any number, the engine must reproduce a published result. Our candidate is the pre-FOMC drift found by Lucca and Moench (2015). They report that the S&P tends to rise in the 24 hours before scheduled Fed announcements. That's cited from memory and must be confirmed against the paper first.

If our engine, run on SPY and real FOMC dates, can't show that effect, the engine is wrong no matter how good its answers look.

10 · Risks

What could break it, and the fallback.

Keiki rewrites our pushes

Its notice API hands our text to Keiki's agent, which rephrases it. Test at H0 whether "8 of 11" survives word for word. iMessage also needs the user to text first and caps new chats at 50 per line per day. The fallback is Telegram straight from Maritime.

Deadline and rubric

Not published. Assume Monday morning IST, and ask at office hours.

Small, clustered samples

Count episodes, show N per asset, say "weak signal" under 8.

Free data terms

Yahoo data is for personal use. Show derived statistics only and cache everything.

Wire reposts inflate confirmation

Count original publishers, not URLs.

Regulation

Impersonal research only, never personal buy or sell calls. Our understanding, not legal advice.
